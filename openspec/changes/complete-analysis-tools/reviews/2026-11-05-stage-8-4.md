# Stage 8.4 — Filter protocol evidence review

## Scope

This stage checks whether the available Analyser 306b recovery proves the hardware command needed to enter Filter/Wobuloscope mode on the user's VNA 1–65 MHz. It does not send commands to the device.

## Findings

- `decompiled/analyser306b/application-pseudocode.c` marks `VB6_00425e1d` as failed because decompilation timed out.
- `decompiled/analyser306b/unrecovered/00425e1d.asm` retains its assembly. String references associate this procedure with the Filter and Generator labels, the `&OFF` caption and a calibration/mode-change message. Those references establish UI mode handling, but do not identify a complete serial command or response contract.
- The MAX4 manual's `1=Wobuloscope` value is evidence about a related device family, not confirmation for the VNA 1–65 MHz variant. Existing driver behavior correctly rejects hardware Filter mode before COM writes.
- The current fixture is a 50 Ω load on ANT with WOB disconnected, so no transmission reference or filter sweep can be validated on the hardware.

## Review

Independent subagent review found no factual or safety blockers. It confirmed that the recovered export does not establish a command for the VNA 1–65 MHz and that the current ANT 50 Ω / open WOB setup cannot validate a transmission fixture. Review caught and resolved the draft status mismatch in this section before completion.

## Remaining work

Confirm the protocol on the exact hardware variant and test only after connecting an ANT–WOB through reference and the filter fixture. Keep the hardware mode blocked until then.
