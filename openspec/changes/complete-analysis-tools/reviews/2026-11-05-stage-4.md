# Stage 4 — Cable Loss review

Review scope: one-port cable loss estimate, open/short fixture gating, session persistence, marker labels, localized UI copy, and method documentation.

The first review found that Cable Loss could be saved in the UI but `CreateSession()` rejected it, and that moving markers did not refresh Cable Loss readouts. Both were fixed and covered by a save/load regression. A follow-up then found the fixture confirmation could carry across a mode change or session load. Confirmation now resets on entry to Cable Loss and on every session load; a regression verifies the plot remains hidden until reconfirmed.

Final independent review found no remaining blockers. Targeted test run: 6 Cable Loss tests passed. UI build passed with 0 warnings/errors (`UsedAvaloniaProducts` empty to avoid inaccessible Avalonia telemetry log).

The implementation reports `−ReturnLossDb / 2` only as a one-port estimate and requires operator confirmation of an open/short cable end. It does not claim full recovery of the original VB6 Cable Loss algorithm or calibration.

An integration pass additionally gated fixture confirmation on hardware Cable Loss provenance, so synthetic demo and unidentified-session data cannot be presented as cable results. Hardware Cable Loss sessions/scans still require fresh fixture confirmation. Follow-up review found no blockers; 7 Cable Loss tests passed.
