# Przegląd workflow release — 2026-11-03

## Zmiany

- Workflow `release.published` z walidacją `vX.Y.Z`, pobieraniem commita release i macierzą sześciu RID Windows/Linux/macOS, x64/ARM64.
- Każdy build uruchamia testy aplikacji i skryptów, publikuje self-contained w Release i sprawdza wersję assembly, RID w deps, obecność runtime, profilu i tłumaczeń.
- ZIP dla Windows; tar.gz dla Linux/macOS. Osobne nazwy zawierają wersję i RID. Plik `release-info.json` pozwala odczytać wersję i cel z rozpakowanej paczki.
- Osobny job `contents: write` sprawdza wszystkie archiwa i hashe przed `gh release upload`. Pozostałe joby mają `contents: read`.

## Ograniczenia

Katalog roboczy nie zawiera `.git` ani zdalnego repozytorium; workflow nie został uruchomiony w GitHub Actions i nie wysyłano załączników do żadnego release. Lokalne publikowanie sprawdzono dla win-x64; pozostałe warianty zostaną zbudowane na runnerach macierzy. Testy ARM64 Windows/Linux uruchamiają się na architekturze hosta builda, nie na urządzeniu docelowym. Pakowanie nie potwierdza zgodności ze sprzętem VNA.

Upload GitHub CLI nie jest atomowy. Powtórzenie workflow odtwarza wygenerowane załączniki o tych samych nazwach. Dokumentację operacyjną zapisano w `docs/RELEASING.md`.
