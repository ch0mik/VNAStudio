# VNA Studio session format

VNA Studio saves completed measurements as UTF-8 JSON (`.vnasession.json`). The root object contains:

An example session that can be opened by the application is available at [`examples/demo.vnasession.json`](examples/demo.vnasession.json).

- `FormatVersion`: current version `6`; versions `1`–`5` are migrated when loaded. Version 4 added the optional `TransmissionDb` sample field used by Filter mode, version 5 added the optional source `PluginId`, and version 6 introduced an optional neutral `ProfileDescriptorSnapshot` for historical presentation.
- `ProfileId`, `PluginId`, optional `ProfileDescriptorSnapshot`, and optional legacy `ProfileSnapshot`: profile/source identity and measurement-time metadata. The neutral descriptor is synthesized from a legacy snapshot when possible and drives historical profile presentation. New sessions write the neutral descriptor; the legacy snapshot remains readable for older files and is retained when an older session is re-saved.
- `AnalysisMode`, `DataSource`, and `CapturedAtUtc`: mode and provenance metadata. Cable Loss saves the underlying reflection samples; Filter saves the separate scalar response in `TransmissionDb`.
- `Sweep`: start/stop frequency and point count.
- `Points`: one entry per frequency, in ascending sweep order. Missing measurements are represented with `null` values and/or a non-`Valid` quality. Display preferences, including RL×2 and the extra RL display offset, are saved separately in `settings.json`; display correction does not rewrite stored session samples.

The reader rejects unsupported versions, invalid snapshots, inconsistent point counts, unknown quality values, non-increasing frequencies, and samples outside the saved start/stop range. Migrations preserve each stored point frequency and sample value; they do not recalculate the sweep grid. Version 1 sessions load as Antenna mode. Saving and loading accept a `CancellationToken`.

To exercise offline playback, open a `.vnasession.json` file, choose **Session playback**, and use **Connect** followed by **Start scan**. A session with a neutral or legacy profile snapshot can be opened without its source plugin, including when its plugin or profile differs from the active hardware configuration. Playback returns the stored points only when the current start/stop frequencies and point count exactly match the session; it does not interpolate or open a COM port. Hardware scans remain disabled when the saved plugin or profile identity differs from the active configuration, except the known `legacy-vna65` migration alias for the matching `iw3hev-65mhz` profile. Opening a session alone displays its saved plot and does not start playback. A session is not a legacy `.vec` format and does not claim compatibility with files from Analyser 306b or vna/J.

For plot comparisons, save or open a named `.vnasnapshot.json` file. Its nested session uses the same validation, migration, provenance, and point-frequency rules as this format. See [comparison snapshots](COMPARISON-SNAPSHOTS.md) for Smith and frequency-chart behavior and the limits of unknown `Zref` or reactance sign.

CSV export is a separate unit-labelled VNA Studio format. The current Studio header includes `Transmission_dB` and `AnalysisMode`; the importer preserves scalar Filter sessions. The previous eight-column Studio header remains supported and loads as Antenna mode. The CSV importer also recognizes the Analyser 306b antenna CSV header recovered from the VB6 writer and an optional Phase(deg) column. Legacy rows preserve only columns present in the file; missing SWR, impedance, resistance, and reactance remain null. The legacy layout was not verified against an actual user-exported CSV sample. Binary .vec files and other undocumented CSV layouts are not supported.
